# HaxPick 划词助手 PRD

## 1. 产品概述

本产品是一个 macOS 菜单栏工具。用户在任意应用内划词后，系统在鼠标附近弹出悬浮工具栏；用户点击具体动作后，应用调用 DeepSeek API 返回翻译、解释、总结等结果。

本次目标是做一个"划词即用、轻量悬浮、低打扰"的桌面效率工具。

## 2. 目标与边界

### 2.1 产品目标

1. 用户划词后 0.3 秒内感知到工具栏出现。
2. 工具栏入口形态、结果面板结构、推荐追问方式简洁高效。
3. 通过 DeepSeek API 完成翻译、解释、总结、润色、改写、提取要点六类 AI 动作，以及原文复制。
4. 保持"即开即用"，不要求用户先打开主窗口。
5. 支持菜单栏常驻、API Key 配置、权限引导和错误可恢复。

### 2.2 非目标

1. 不做多会话聊天列表。
2. 不做文档管理、历史记录云同步。
3. 不做复杂插件系统。
4. 不追求首版功能完备，核心交互和视觉层级优先。
5. 不解决所有应用的划词兼容性；首版优先通过 Accessibility API 读取选中文本，并对无法读取的应用提供模拟 ⌘C 剪贴板兜底方案。

## 3. 目标用户

1. 经常阅读英文网页、PDF、技术文档的 macOS 用户。
2. 需要快速翻译、解释、总结段落的开发者、学生、研究人员。
3. 希望"划词后立刻得到结果"的轻量 AI 工具用户。

## 4. 核心使用场景

### 4.1 划词翻译

用户在浏览器或文档中选中英文短语或句子，松开鼠标后弹出工具栏，点击"翻译"，面板展示中文翻译结果。

### 4.2 划词解释

用户选中陌生术语、段落或一句话，点击"解释"，面板用简洁中文解释含义，并在必要时补充背景信息。

### 4.3 划词总结

用户选中较长文本，点击"总结"，面板返回简明重点摘要。

### 4.4 划词润色

用户选中中文文本，点击"润色"，在不改变原意的前提下优化表达。

### 4.5 划词改写

用户选中文本，点击"改写"，获得更流畅的不同表达版本。

### 4.6 提取要点

用户选中较长的说明性或论述性文本，点击"提取要点"，返回一句话概述 + 3~5 条要点。

### 4.7 继续追问

用户对当前结果继续点击推荐问题，或在底部输入框输入补充问题，例如"换个更简单的说法""举个例子""这句话为什么这么翻译"。追问复用当前上下文（原文 + 上一轮结果）继续请求 DeepSeek。

## 5. 信息架构

产品包含 3 个主界面：

1. 菜单栏入口
2. 划词工具栏
3. 结果悬浮面板

### 5.1 菜单栏入口

职责：

1. 展示应用运行状态
2. 配置 DeepSeek API Key
3. 引导开启辅助功能权限
4. 提供退出入口

实现方式：SwiftUI `MenuBarExtra`，`.menuBarExtraStyle(.window)` 模式，窗口宽度 340pt。

### 5.2 划词工具栏

职责：

1. 在用户完成划词后立即出现
2. 提供横向动作按钮
3. 作为"轻入口"，点击动作后展开结果面板或直接执行

主工具栏动作（5 个直接可见）：

1. 复制 — 直接复制原文，不展开面板，按钮位置显示短暂成功反馈
2. 翻译
3. 解释
4. 总结
5. 更多 — 下拉菜单展开

"更多"菜单中包含：

1. 润色
2. 改写
3. 提取要点

工具栏尺寸：480×60pt，圆角 14pt，浅灰底色 + 白色胶囊按钮，扁平无阴影。

### 5.3 结果悬浮面板

职责：

1. 展示当前任务结果
2. 提供复制、重试、关闭、继续追问
3. 提供推荐追问 chips
4. 支持原文展开/收起（超过 140 字符默认折叠）

面板尺寸：440×548pt，圆角 14pt，扁平无阴影。

面板内部分区：

1. **顶部标题区** — 左侧渐变色圆形图标 + 动作标题 + 状态提示 + 右侧关闭按钮
2. **原文区** — 本次划词原文，默认最多显示 140 字符（超出可展开），弱文字色，支持复制
3. **结果内容区** — 核心阅读区，220pt 高度可滚动，结果文本支持选择复制
4. **底部操作栏** — 重新生成、复制结果、关闭
5. **继续提问区** — 推荐追问 chips（横向滚动）+ 输入框 + 发送按钮

## 6. 交互流程

### 6.1 主流程

1. 用户首次启动应用。
2. 应用检查 DeepSeek API Key 和辅助功能权限。
3. 若未授权，则在菜单栏面板中提示用户完成配置。
4. 用户在任意目标应用中划词（鼠标拖动距离 ≥ 8pt 才视为有效划词）。
5. 鼠标松开后，等待 150ms 让系统完成选中状态的更新。
6. **双通道读取选中文本：**
   - **通道一**：在 `mouseUp` 当下先抓一份早期 Accessibility 选区快照，再尝试通过 Accessibility API 读取 `kAXSelectedTextAttribute`，并利用 `kAXBoundsForRangeParameterizedAttribute` 计算选中文本的屏幕坐标作为面板锚点；若目标应用自己的划词工具栏让后续选区消失，可回退到早快照。
   - **通道二**：若 Accessibility 读取失败，仅在当前焦点元素仍像文本控件，或角色为浏览器 Web 内容区域（如 `AXWebArea`）时才模拟 ⌘C 从剪贴板获取选中文本。此过程会先保存当前剪贴板内容，写入标记字符串，发送 ⌘C，并在最多 400ms 的短轮询窗口内一旦读到文本就立即恢复原始剪贴板；若截图工具或用户操作已先改写剪贴板，则不再强行恢复旧内容。
7. 若成功读到文本，在鼠标附近弹出划词工具栏（面板位置根据选中文本 bounds 计算，同时限制在屏幕可视区域内）。
   - 首层工具栏只悬浮展示，不主动抢占前台焦点，且保持 `hidesOnDeactivate = false`，避免在 app 未激活时刚显示就被系统自动收起。
8. 用户点击 AI 动作。
9. 工具栏切换为结果面板（先显示加载态）。
   - 进入结果面板后再激活 HaxPick，以支持键盘关闭、继续提问和后续交互。
10. DeepSeek 返回结果后展示正文与推荐追问。
11. 用户可复制结果、继续追问、重新生成、关闭面板。

### 6.2 去重与忽略逻辑

1. 同一段文本 1.2 秒内不会重复触发。
2. 用户通过关闭面板"忽略"的选中文本，不会再次触发工具栏（直到用户执行一次新的有效划词拖动）。

### 6.3 关闭面板的方式

1. 点击面板内"关闭"按钮。
2. 按 ESC 键。
3. 点击面板外任意位置。

### 6.4 异常流程

1. 未读取到选中文本：不弹工具栏，在菜单栏状态中提示"当前应用未返回可读取的选中文本"。
2. 未配置 API Key：点击动作后在结果区提示"请先在菜单栏面板里填写 DeepSeek API Key"。
3. 请求失败（401/429/5xx 等）：在结果区展示可读错误信息，并提供"重试"按钮。
4. 用户再次划词：关闭旧面板，基于新选中文本重新打开。
5. 辅助功能权限未开启：菜单栏状态提示"请先开启辅助功能权限"，划词不触发工具栏。

## 7. UI 与交互要求

### 7.1 整体设计方向

整体设计方向：

1. 小而轻的横向工具栏入口
2. 白色不透明卡片式悬浮面板，亮色主题，扁平化无阴影
3. 统一圆角 14pt，纯色块分隔，粗细字体形成层级
4. 工具按钮优先使用图标 + 短文案，无阴影胶囊样式
5. 内容区以阅读舒适为第一优先级

macOS 侧实现方式：

1. 使用浮层 `NSPanel`（`.borderless` + `.nonactivatingPanel` + `.fullSizeContentView`）
2. 标题栏隐藏，但通过 `.isMovableByWindowBackground` 支持拖拽
3. 面板层级 `.floating`，避免被普通窗口遮挡
4. `collectionBehavior` 设为 `[.canJoinAllSpaces, .fullScreenAuxiliary]`
5. `hidesOnDeactivate = true`，切换应用时自动隐藏

### 7.2 划词工具栏布局

工具栏默认仅一行，宽度 478pt，高度 60pt（含 10pt 内边距），内容从左到右排列：

1. 复制（doc.on.doc）
2. 翻译（globe）
3. 解释（text.bubble）
4. 总结（list.bullet.rectangle）
5. 更多（ellipsis + chevron.down）

交互要求：

1. 按钮使用白色胶囊样式，hover 有浅灰背景反馈。
2. 点击"复制"直接复制原文，按钮位置弹出短暂绿色"已复制原文"提示，不展开结果面板。
3. 点击 AI 动作后，工具栏切换为结果面板（直接替换，无转场动画）。
4. "更多"按钮使用 `Menu` 下拉菜单样式。

### 7.3 结果面板布局

结果面板参考设计规范，分为 5 个区域，面板宽度 436pt（含 16pt 内边距），内容宽度 404pt，高度 548pt：

#### 7.3.1 顶部标题区

包含：

1. 左侧渐变色圆形图标（28×28pt）+ 当前动作 SFSymbol 图标
2. 标题文案，如"这里是我的翻译 / 这里是我的解释 / 这里是我的润色 / 这里是我的改写 / 这里是我的提取要点"
3. 状态副标题（"正在生成..." / "生成完成" / "请求失败，可重试"）
4. 右侧关闭按钮

规则：

1. 标题随当前动作变化。
2. 面板支持关闭。

#### 7.3.2 原文区

展示本次划词原文。

规则：

1. 原文与结果视觉区分，原文使用浅灰色文字，背景为浅灰卡片。
2. 支持点击"复制原文"按钮复制。
3. 超过 140 字符默认折叠，显示"展开更多"按钮；点击后切换为"收起"。
4. 原文文本支持选择复制。

#### 7.3.3 结果内容区

核心阅读区域，高度 220pt 可滚动。

规则：

1. 结果文本支持选择和复制。
2. 加载中且无结果时显示"正在生成内容，请稍候..."占位文字。
3. 无结果时显示"点击上方动作后，这里会展示结果。"引导文案。
4. 错误时直接展示错误信息。
5. 返回内容过长时内容区内部滚动，面板外框尺寸保持稳定。

#### 7.3.4 底部操作栏

已实现的按钮：

1. 重新生成（浅蓝色胶囊按钮）
2. 复制结果（白色胶囊按钮）
3. 关闭（白色胶囊按钮）

可延后：

1. TTS 朗读
2. 点赞/点踩反馈

#### 7.3.5 继续提问区

包含：

1. 一个输入框，placeholder 为"继续提问"
2. 横向滚动的推荐问题 chips（每项动作有 3 个预置建议问题）
3. 发送按钮（蓝色胶囊，带阴影）

推荐问题按动作分类：

- **翻译**："这句话为什么这样翻译？"、"换一个更自然的说法"、"给我一个例句"
- **解释**："用更简单的话解释"、"给我一个例子"、"这背后的背景是什么？"
- **总结**："提炼成 3 个要点"、"给我一个更短版本"、"哪些信息最重要？"
- **润色**："更正式一点"、"更口语一点"、"保留原意再简洁些"
- **改写**："换一种表达方式"、"适合邮件场景"、"适合口语场景"
- **提取要点**："按 bullet 再整理"、"只保留结论"、"提取可执行事项"

规则：

1. 推荐问题基于当前动作生成。
2. 用户点击推荐问题或输入框发送后，复用当前原文 + 上一轮结果继续请求 DeepSeek。
3. 追问发送后输入框自动清空。
4. 追问结果替换当前结果区内容（不追加）。

## 8. 功能需求

### 8.1 选中文本监听与获取

需求：

1. 监听全局鼠标按下和抬起事件，计算拖动距离（≥ 8pt 才视为有效划词）。
2. 鼠标抬起后等待 150ms，确保系统完成选中状态更新。
3. **第一优先**：通过 Accessibility API 获取选中文本（`kAXSelectedTextAttribute`）。
4. **第二优先（兜底）**：若 Accessibility 读取失败，通过模拟 ⌘C 按键获取选中文本。此过程：
   - 先保存当前剪贴板全部内容（支持多类型数据）。
   - 写入唯一标记字符串到剪贴板。
   - 发送 CGEvent ⌘C 按键。
   - 仅在当前焦点元素仍暴露文本相关 AX 属性时执行，避免对截图/非文本场景误触发。
   - 在最多 400ms 的短轮询窗口内读取剪贴板文本，读到结果后立即结束等待。
   - 仅在剪贴板仍由本流程占用时恢复原始剪贴板内容；若外部程序已写入新内容则直接让外部结果保留。
   - 若读取到的文本与标记字符串相同或为空，视为读取失败。
5. 过滤空文本、纯空白文本。
6. 通过 `kAXBoundsForRangeParameterizedAttribute` 计算选中文本的屏幕坐标，作为面板锚点。
7. 坐标合理性校验：anchor 距离 fallback 点不超过 260pt，距离鼠标松开点不超过 320pt，否则回退到鼠标位置中点。

验收：

1. 在 Safari、Chrome、Edge、Xcode、Notes 中进行兼容性测试。
2. Accessibility 不可用时自动回退到 ⌘C 方案，用户在大部分应用中无感知。
3. 对于两种方式都无法读取的应用，在菜单栏状态中给出明确提示，不出现卡死或无响应。

### 8.2 DeepSeek 请求能力

需求：

1. 支持 `deepseek-chat` 模型。
2. 根据不同动作拼接不同 system/user prompt。
3. 支持继续追问时带上当前选中文本和最近一次结果上下文。
4. 正确处理接口错误信息并展示给用户。
5. 请求超时时间 45 秒。

验收：

1. API Key 缺失、401、429、5xx 均能给用户可理解错误提示。
2. 请求中断后可以重试。

### 8.3 菜单栏配置

需求：

1. 支持输入与保存 API Key（存储于 UserDefaults，`deepseek_api_key` key）。
2. 支持查看权限状态（实时展示 `AXIsProcessTrusted()` 结果）。
3. 支持打开系统辅助功能设置。
4. 支持查看当前模型（deepseek-chat）和应用版本。

实现细节：

1. API Key 当前存储于 `UserDefaults`（`deepseek_api_key` key）。
2. 应用内置默认 API Key，用户可直接替换为自己的 Key。

### 8.4 上下文管理

1. 不做完整历史记录页。
2. 单次面板内保留本轮追问上下文（原文 + 上一轮结果）。
3. 面板关闭后默认清空上下文。
4. 每次新划词会重置所有状态（动作、结果、追问输入等）。

### 8.5 快捷操作

已实现：

1. 复制原文（工具栏按钮 + 面板内按钮）
2. 复制结果（面板底部按钮，带"已复制结果"反馈提示）
3. 重新生成
4. ESC 键关闭面板
5. 点击面板外关闭

可延后：

1. 全局快捷键唤起
2. 最近一次结果再次打开

## 9. 状态设计

### 9.1 工具栏状态

1. 隐藏态
2. 已识别文本待操作态
3. 点击"复制"后的短暂反馈态
4. 点击 AI 动作后切换为结果面板

### 9.2 结果面板状态

1. 加载中 — 显示 ProgressView + "正在生成..."提示
2. 成功 — 展示结果正文与推荐追问
3. 失败 — 展示可读错误文案 + "重试"按钮
4. 无权限 — 在菜单栏状态中提示
5. 未配置 API Key — 点击动作后在结果区提示

### 9.3 文案原则

1. 短句优先
2. 错误要可行动
3. 不把接口原始报错直接裸露给用户，优先解析 JSON error message 字段

## 10. Prompt 策略

### 10.1 翻译

System prompt：翻译助手，输出简洁、自然、结构化。
User prompt：
- 单词/短语：输出主要译文 → 词性/音标 → 常见搭配 → 例句
- 句子/段落：优先自然中文，不做逐词硬译

### 10.2 解释

System prompt：解释助手，先给简要解释，再分点说明，必要时补充背景。
User prompt：简要解释 → 分点解析 → 必要背景补充 → 一句话总结

### 10.3 总结

System prompt：总结助手，先给一句总述，再给 2~4 条要点。
User prompt：一句话总结 → 2~4 条重点 bullet

### 10.4 润色

System prompt：中文润色助手，不改变原意的前提下优化表达，输出直接可用。
User prompt：润色原文，让表达更自然、清晰、简洁。

### 10.5 改写

System prompt：改写助手，根据原文进行不同表达方式的改写，保持自然、清晰。
User prompt：不改变原意的前提下改写，给出更流畅的表达版本。

### 10.6 提取要点

System prompt：总结助手（与总结共用 system prompt）。
User prompt：一句话概述 → 3~5 条要点。

### 10.7 继续追问

User prompt 结构：
```
当前原文：
{原文}

上一轮结果：
{上一轮结果}

用户继续提问：
{追问内容}

请基于当前任务类型继续回答，保持结构化、简洁，适合桌面悬浮面板阅读。
```

## 11. 性能与体验要求

1. 工具栏弹出耗时目标小于 300ms（含 150ms 等待 + Accessibility 读取时间）。
2. 模拟 ⌘C 兜底方案采用最多 400ms 的短轮询等待；多数成功路径会在检测到结果后立即结束，最坏情况下总耗时约 630ms。
3. 结果首屏反馈取决于 DeepSeek API 响应速度；必须先展示 loading 态。
4. 面板位置必须被限制在当前屏幕可视区域内（边缘留 12pt 安全间距）。
5. 再次划词时旧内容应被新任务替换，不残留旧状态。

## 12. 技术约束

1. 平台仅限 macOS 13+。
2. 使用 `NSPanel + SwiftUI（NSHostingView）` 实现悬浮面板。
3. 读取划词内容双通道：Accessibility API + 模拟 ⌘C 剪贴板兜底。
4. 无标题栏浮层通过 `.borderless` + `.fullSizeContentView` 实现，通过 `.isMovableByWindowBackground` 保留拖拽能力。
5. 应用入口为菜单栏模式（`.menuBarExtra`），激活策略为 `.accessory`（无 Dock 图标）。
6. Swift Package Manager 管理依赖，Xcode 项目文件用于构建和签名配置。

## 13. 验收标准

### 13.1 功能验收

1. 用户完成 API Key 配置和权限授权后，可以在至少 3 个常见应用中稳定划词触发工具栏。
2. 翻译、解释、总结、润色、改写、提取要点六个 AI 动作均能返回结果。
3. 支持继续提问（推荐问题 chips + 自由输入）。
4. 支持复制原文、复制结果、重试、关闭。
5. Accessibility 不可用的应用能通过 ⌘C 兜底方案正常获取选中文本。
6. ⌘C 兜底方案不应覆盖截图工具或用户在同一时间窗口内写入的新剪贴板内容。

### 13.2 交互验收

1. 工具栏横向按钮形态清晰，交互流畅。
2. 结果面板的顶部、原文区、内容区、底部操作栏、继续提问区层级清晰。
3. 加载态、错误态、成功态切换自然，无明显闪烁。
4. 面板不会出现在屏幕外或被 Dock/Menu Bar 遮挡。
5. ESC 键和点击面板外均能关闭面板。

### 13.3 视觉验收

1. 视觉风格为扁平化白色卡片，无阴影无渐变，纯色块分隔，不做厚重桌面窗口感。
2. 图标、间距、圆角统一 14pt，按钮样式一致。
3. 信息密度适中，层级靠字重和底色区分。

## 15. 实现架构

### 15.1 组件关系

```
HaxPickApp (SwiftUI @main, MenuBarExtra)
  └── AppDelegate (启动入口)
        └── AppState (单例，中心状态管理)
              ├── SelectionMonitor (全局鼠标事件监听)
              │     ├── AccessibilityTextService (通道一：辅助功能 API)
              │     └── ClipboardSelectionService (通道二：模拟 ⌘C)
              ├── ToolbarPanelController (NSPanel 管理)
              │     ├── PanelSessionViewModel (面板状态)
              │     └── FloatingToolbarView (SwiftUI 视图)
              └── DeepSeekService (API 请求)
```

### 15.2 关键文件

| 文件 | 职责 |
|------|------|
| `HaxPickApp.swift` | 应用入口，MenuBarExtra UI |
| `AppDelegate.swift` | 启动回调 |
| `AppState.swift` | 单例状态管理，协调各组件 |
| `SelectionMonitor.swift` | 全局鼠标事件监听，划词检测 |
| `AccessibilityTextService.swift` | 通过 AX API 读取选中文本和坐标 |
| `ClipboardSelectionService.swift` | 模拟 ⌘C 获取文本，剪贴板保存/恢复 |
| `ToolbarPanelController.swift` | NSPanel 创建、定位、事件处理 |
| `FloatingToolbarView.swift` | SwiftUI 工具栏/结果面板视图 + ViewModel |
| `DeepSeekService.swift` | DeepSeek API 调用、Prompt 构建、错误处理 |
| `Package.swift` | Swift Package Manager 配置 |

## 16. 当前假设

1. "完全参考HaxPick"理解为产品交互、布局和信息层级对齐，不代表需要品牌素材、图标或文案逐字复刻。
2. "依赖 DeepSeek API"理解为模型服务端完全使用 DeepSeek，不接第三方中转层。
3. 当前项目继续沿用现有 macOS App 架构，不改成浏览器扩展或输入法插件。
4. 双通道划词读取方案可覆盖主流 macOS 应用的绝大多数场景。
