# HaxPick 划词助手 PRD

## 1. 产品概述

本产品是一个 macOS 菜单栏工具。用户在任意应用内划词后，系统在鼠标附近弹出悬浮工具栏；用户点击具体动作后，应用调用 DeepSeek API 返回翻译或解释结果，并将结果固定展示在屏幕右侧侧栏。

本次目标是做一个"划词即用、轻量悬浮、低打扰"的桌面效率工具。

## 2. 目标与边界

### 2.1 产品目标

1. 用户划词后 0.3 秒内感知到工具栏出现。
2. 工具栏入口形态、结果面板结构、推荐追问方式简洁高效。
3. MVP 通过 DeepSeek API 完成翻译、解释两类 AI 动作，以及原文复制。
4. 保持"即开即用"，不要求用户先打开主窗口。
5. 支持菜单栏常驻、API Key 配置、权限引导和错误可恢复。

### 2.2 非目标

1. 不做多会话聊天列表。
2. 不做文档管理、历史记录云同步。
3. 不做复杂插件系统。
4. 不追求首版功能完备，核心交互和视觉层级优先。
5. 不承诺覆盖所有私有渲染控件；首版必须稳定覆盖主流浏览器、IDE 与 Codex 对话界面，并通过 Accessibility API + 模拟 ⌘C 双通道处理无法直接读取的文本区域。

## 3. 目标用户

1. 经常阅读英文网页、PDF、技术文档的 macOS 用户。
2. 需要快速翻译、解释段落的开发者、学生、研究人员。
3. 希望"划词后立刻得到结果"的轻量 AI 工具用户。

## 4. 核心使用场景

### 4.1 划词翻译

用户在浏览器或文档中拖动选中英文短语或句子；划出第一个词时工具栏即出现，松开鼠标后以最终选区更新内容。点击"翻译"后，面板展示中文翻译结果。

### 4.2 划词解释

用户选中陌生术语、段落或一句话，点击"解释"，面板用简洁中文解释含义，并在必要时补充背景信息。

### 4.3 继续追问

用户对当前结果继续点击推荐问题，或在底部输入框输入补充问题，例如"换个更简单的说法""举个例子""这句话为什么这么翻译"。追问复用当前上下文（原文 + 上一轮结果）继续请求 DeepSeek。

## 5. 信息架构

产品包含 3 个主界面：

1. 菜单栏入口
2. 划词工具栏
3. 结果悬浮面板

### 5.1 菜单栏入口

职责：

1. 展示应用运行状态
2. 配置 DeepSeek API Key
3. 引导开启辅助功能权限
4. 提供退出入口

实现方式：SwiftUI `MenuBarExtra`，`.menuBarExtraStyle(.window)` 模式，窗口宽度 320pt。面板使用 8pt 磨砂玻璃外缘和不透明浅色内容层；权限正常时权限区收敛为单行状态。

### 5.2 划词工具栏

职责：

1. 在用户划出第一个词时立即出现，不等待鼠标松开
2. 提供横向动作按钮
3. 作为"轻入口"，点击动作后展开结果面板或直接执行

主工具栏内容：

1. 品牌图标与选中文字数
2. 复制 — 直接复制原文，不展开结果侧栏
3. 翻译
4. 解释

工具栏尺寸：378×48pt，圆角 15pt，使用深色磨砂玻璃外壳、内外同心倒角和橙色主动作态。

### 5.3 结果悬浮面板

职责：

1. 展示当前任务结果
2. 提供复制、重试、关闭、继续追问
3. 提供推荐追问 chips
4. 支持原文展开/收起（超过 140 字符默认折叠）

结果侧栏固定在当前屏幕右侧，宽度占屏幕可用宽度的 36%（限制在 460–560pt），高度占可用区域的 82%（限制在 560–720pt），右侧保留 16pt 并垂直居中。外壳圆角 28pt，采用 12pt 宽高透明磨砂玻璃外缘；主题内容层为白色磨砂微透明，输入框保持更高不透明度。

面板内部分区：

1. **顶部标题区** — 左侧品牌图标 + 动作标题 + 状态提示 + 右侧关闭按钮
2. **原文区** — 本次划词原文，默认最多显示 140 字符（超出可展开），弱文字色，支持复制
3. **结果内容区** — 占据侧栏剩余空间并可滚动，结果文本支持选择复制
4. **底部操作栏** — 重新生成、复制结果
5. **继续提问区** — 推荐追问 chips（横向滚动）+ 输入框 + 发送按钮

## 6. 交互流程

### 6.1 主流程

1. 用户首次启动应用。
2. 应用检查 DeepSeek API Key 和辅助功能权限。
3. 若未授权，则在菜单栏面板中提示用户完成配置。
4. 用户在任意目标应用中划词（鼠标拖动距离 ≥ 3pt 视为有效划词）。
5. `mouseDragged` 阶段立即启动双通道读取：
   - **通道一**：先通过 Accessibility API 读取 `kAXSelectedTextAttribute`；若首次尚未形成选区，35ms 后重试，并利用 `kAXBoundsForRangeParameterizedAttribute` 计算面板锚点。
   - **通道二**：若 Accessibility 读取失败，检查焦点元素、鼠标当前位置、拖动起点下方的文本元素及父层级；网页、IDE、Codex 或文本控件进入快速模拟 ⌘C 兜底，仅使用 CGEvent 并最多等待 160ms。
6. 划出第一个可读词后立即在鼠标附近弹出工具栏，无需等待 `mouseUp`；面板位置限制在屏幕可视区域内，首层工具栏不抢前台焦点。
7. `mouseUp` 后等待 35ms，并通过 AX 重试 + 完整模拟 ⌘C 兜底（CGEvent + AppleScript，最多 400ms）读取最终选区；若与拖动阶段结果不同，原位更新工具栏文本。
   - 模拟复制会保存原剪贴板；取消或超时后恢复，若外部程序已写入新内容则保留外部结果。
   - 首层工具栏只悬浮展示，不主动抢占前台焦点，且保持 `hidesOnDeactivate = false`，避免在 app 未激活时刚显示就被系统自动收起。
8. 用户点击 AI 动作。
9. 工具栏切换为结果侧栏（先显示加载态）。
   - 侧栏固定在当前屏幕右侧，进入后再激活 HaxPick，以支持键盘关闭、继续提问和后续交互。
   - 侧栏保持显示，点击侧栏外不会自动关闭。
10. DeepSeek 返回结果后展示正文与推荐追问。
11. 用户可复制结果、继续追问、重新生成、关闭面板。

### 6.2 去重与忽略逻辑

1. 同一段文本 1.2 秒内不会重复触发。
2. 用户通过关闭面板"忽略"的选中文本，不会再次触发工具栏（直到用户执行一次新的有效划词拖动）。

### 6.3 关闭面板的方式

1. 点击面板内"关闭"按钮。
2. 按 ESC 键。
3. 工具栏状态下点击面板外任意位置；结果侧栏状态不响应外部点击关闭。

### 6.4 异常流程

1. 未读取到选中文本：不弹工具栏，在菜单栏状态中提示"当前应用未返回可读取的选中文本"。
2. 未配置 API Key：点击动作后在结果区提示"请先在菜单栏面板里填写 DeepSeek API Key"。
3. 请求失败（401/429/5xx 等）：在结果区展示可读错误信息，并提供"重试"按钮。
4. 用户再次划词：关闭旧面板，基于新选中文本重新打开。
5. 辅助功能权限未开启：菜单栏状态提示"请先开启辅助功能权限"，划词不触发工具栏。

## 7. UI 与交互要求

### 7.1 整体设计方向

整体设计方向：

1. 小而轻的横向工具栏入口
2. macOS 26 Liquid Glass 风格的悬浮控制层，玻璃用于工具栏、结果侧栏和菜单栏面板外壳
3. 工具栏圆角 15pt、结果侧栏圆角 28pt，外侧高光与内侧暗边形成同心倒角，表现玻璃厚度
4. 工具按钮使用 SF Symbols + 短文案，当前动作以品牌橙色胶囊强调
5. 内容区以阅读舒适为第一优先级
6. 原文和结果长文本使用白色磨砂微透明背景，继续提问输入框保持更高不透明度

macOS 侧实现方式：

1. 使用浮层 `NSPanel`（`.borderless` + `.nonactivatingPanel` + `.fullSizeContentView`）
2. 标题栏隐藏；工具栏可拖动，结果侧栏固定在屏幕右侧
3. 面板层级 `.floating`，避免被普通窗口遮挡
4. `collectionBehavior` 设为 `[.canJoinAllSpaces, .fullScreenAuxiliary]`
5. 两种模式均使用 `hidesOnDeactivate = false`；结果侧栏在切换应用后保持显示
6. macOS 26 / Xcode 26 构建使用 SwiftUI `glassEffect`，旧 SDK 和 macOS 13–15 使用 `NSVisualEffectView` 回退

### 7.2 划词工具栏布局

工具栏默认仅一行，宽度 378pt，高度 48pt，内容从左到右排列：

1. 品牌图标
2. 选中文字数
3. 复制（doc.on.doc）
4. 翻译（globe）
5. 解释（text.bubble）
	
交互要求：

1. 工具栏使用深色磨砂材质，操作按钮使用半透明胶囊，hover/按压提供明度反馈。
2. 工具栏支持按住空白位置拖动移动，不额外展示拖动把手。
3. 点击"复制"直接复制原文并关闭工具栏，不展开结果侧栏。
3. 点击翻译或解释后，工具栏切换为右侧结果侧栏。
4. MVP 不展示总结、润色、改写、提取要点或“更多”入口。

### 7.3 结果面板布局

结果侧栏分为 5 个区域，宽度为屏幕可用宽度的 36%（460–560pt），高度为屏幕可用高度的 82%（560–720pt），固定在右侧并垂直居中。白色阅读层与玻璃外缘之间保留 12pt 内边距；玻璃外侧高光与内侧暗边形成可见倒角，白色层圆角与外壳保持同心：

#### 7.3.1 顶部标题区

包含：

1. 左侧品牌图标（36×36pt）
2. 标题文案为"翻译"或"解释"
3. 状态副标题（"正在生成..." / "生成完成" / "请求失败，可重试"）
4. 右侧关闭按钮

规则：

1. 标题随当前动作变化。
2. 面板支持关闭。

#### 7.3.2 原文区

展示本次划词原文。

规则：

1. 原文与结果通过字重、间距和带水平内边距的 0.5pt 弱分隔线区分，不使用嵌套玻璃卡片。
2. 支持点击"复制原文"按钮复制。
3. 超过 140 字符默认折叠，显示"展开更多"按钮；点击后切换为"收起"。
4. 原文文本支持选择复制。

#### 7.3.3 结果内容区

核心阅读区域占据侧栏剩余高度并可滚动。

规则：

1. 结果文本支持选择和复制。
2. 加载中且无结果时显示"正在生成内容，请稍候..."占位文字。
3. 无结果时显示"点击上方动作后，这里会展示结果。"引导文案。
4. 错误时直接展示错误信息。
5. 返回内容过长时内容区内部滚动，侧栏位置和外框尺寸保持稳定。

#### 7.3.4 底部操作栏

已实现的按钮：

1. 重新生成（内联图标 + 文案）
2. 复制结果（内联图标 + 文案）

可延后：

1. TTS 朗读
2. 点赞/点踩反馈

#### 7.3.5 继续提问区

包含：

1. 一个纯白不透明输入框，placeholder 为"继续提问..."，输入框不使用玻璃材质
2. 横向滚动的推荐问题 chips（每项动作有 3 个预置建议问题）
3. 发送按钮（品牌橙色圆形按钮）

推荐问题按动作分类：

- **翻译**："这句话为什么这样翻译？"、"换一个更自然的说法"、"给我一个例句"
- **解释**："用更简单的话解释"、"给我一个例子"、"这背后的背景是什么？"

规则：

1. 推荐问题基于当前动作生成。
2. 用户点击推荐问题或输入框发送后，复用当前原文 + 上一轮结果继续请求 DeepSeek。
3. 追问发送后输入框自动清空。
4. 追问结果追加在当前单次会话内，并自动跟随到最新内容；用户手动滚动后暂停自动跟随。

## 8. 功能需求

### 8.1 选中文本监听与获取

需求：

1. 监听全局鼠标按下、拖动和抬起事件，计算拖动距离（≥ 3pt 视为有效划词）。
2. 拖动阶段立即尝试 Accessibility 读取，并在 35ms 后快速重试；不得等待 `mouseUp` 才开始检测。
3. **第一优先**：通过 Accessibility API 获取选中文本（`kAXSelectedTextAttribute`），覆盖焦点元素、鼠标下方元素及父层级。
4. **第二优先（兜底）**：若 Accessibility 读取失败，在文本控件或浏览器、IDE、Codex 等已知文本应用中通过模拟 ⌘C 获取选中文本。此过程：
   - 先保存当前剪贴板全部内容（支持多类型数据）。
   - 写入唯一标记字符串到剪贴板。
   - 发送 CGEvent ⌘C 按键。
   - 拖动阶段仅发送 CGEvent，最多等待 160ms；抬起后可使用 CGEvent + AppleScript，最多等待 400ms。
   - 根据焦点元素、鼠标下元素及其父层级的 AX 角色/属性判断；已知文本应用使用 bundle ID 兜底，避免 Electron/WebView 外层 Group 导致漏判。
   - 短轮询读取剪贴板文本，读到结果后立即结束等待。
   - 仅在剪贴板仍由本流程占用时恢复原始剪贴板内容；若外部程序已写入新内容则直接让外部结果保留。
   - 若读取到的文本与标记字符串相同或为空，视为读取失败。
5. 过滤空文本、纯空白文本。
6. 通过 `kAXBoundsForRangeParameterizedAttribute` 计算选中文本的屏幕坐标，作为面板锚点。
7. 坐标合理性校验：anchor 距离 fallback 点不超过 260pt，距离鼠标松开点不超过 320pt，否则回退到鼠标位置中点。

验收：

1. 在 Safari、Chrome、Edge、Xcode、Notes 中进行兼容性测试。
2. Accessibility 不可用时自动回退到 ⌘C 方案，用户在大部分应用中无感知。
3. 对于两种方式都无法读取的应用，在菜单栏状态中给出明确提示，不出现卡死或无响应。

### 8.2 DeepSeek 请求能力

需求：

1. 支持 `deepseek-chat` 模型。
2. 根据不同动作拼接不同 system/user prompt。
3. 支持继续追问时带上当前选中文本和最近一次结果上下文。
4. 正确处理接口错误信息并展示给用户。
5. 请求超时时间 45 秒。

验收：

1. API Key 缺失、401、429、5xx 均能给用户可理解错误提示。
2. 请求中断后可以重试。

### 8.3 菜单栏配置

需求：

1. 支持输入与保存 API Key（存储于 UserDefaults，`deepseek_api_key` key）。
2. 支持查看权限状态（实时展示 `AXIsProcessTrusted()` 结果）。
3. 支持打开系统辅助功能设置。
4. 支持查看当前模型（deepseek-chat）和应用版本。

实现细节：

1. API Key 当前存储于 `UserDefaults`（`deepseek_api_key` key）。
2. 应用内置默认 API Key，用户可直接替换为自己的 Key。

### 8.4 上下文管理

1. 不做完整历史记录页。
2. 单次面板内保留本轮追问上下文（原文 + 上一轮结果）。
3. 面板关闭后默认清空上下文。
4. 每次新划词会重置所有状态（动作、结果、追问输入等）。

### 8.5 快捷操作

已实现：

1. 复制原文（工具栏按钮 + 面板内按钮）
2. 复制结果（面板底部按钮，带"已复制结果"反馈提示）
3. 重新生成
4. ESC 键关闭面板
5. 工具栏模式点击面板外关闭

可延后：

1. 全局快捷键唤起
2. 最近一次结果再次打开

## 9. 状态设计

### 9.1 工具栏状态

1. 隐藏态
2. 已识别文本待操作态
3. 点击"复制"后的短暂反馈态
4. 点击 AI 动作后切换为结果面板

### 9.2 结果面板状态

1. 加载中 — 显示 ProgressView + "正在生成..."提示
2. 成功 — 展示结果正文与推荐追问
3. 失败 — 展示可读错误文案 + "重试"按钮
4. 无权限 — 在菜单栏状态中提示
5. 未配置 API Key — 点击动作后在结果区提示

### 9.3 文案原则

1. 短句优先
2. 错误要可行动
3. 不把接口原始报错直接裸露给用户，优先解析 JSON error message 字段

## 10. Prompt 策略

### 10.1 翻译

System prompt：翻译助手，输出简洁、自然、结构化。
User prompt：
- 单词/短语：输出主要译文 → 词性/音标 → 常见搭配 → 例句
- 句子/段落：优先自然中文，不做逐词硬译

### 10.2 解释

System prompt：解释助手，先给简要解释，再分点说明，必要时补充背景。
User prompt：简要解释 → 分点解析 → 必要背景补充 → 一句话总结

### 10.3 继续追问

User prompt 结构：
```
当前原文：
{原文}

上一轮结果：
{上一轮结果}

用户继续提问：
{追问内容}

请基于当前任务类型继续回答，保持结构化、简洁，适合桌面悬浮面板阅读。
```

## 11. 性能与体验要求

1. 划出第一个词后工具栏应在鼠标仍按下时出现；AX 成功路径应随拖动事件立即反馈，快速兜底目标小于 200ms（35ms 重试 + 最多 160ms 剪贴板探测）。
2. `mouseUp` 后的最终模拟 ⌘C 兜底采用最多 400ms 的短轮询，仅用于补齐或校正最终选区，不阻塞已显示的工具栏。
3. 结果首屏反馈取决于 DeepSeek API 响应速度；必须先展示 loading 态。
4. 工具栏位置必须被限制在当前屏幕可视区域内；结果侧栏固定在当前屏幕右侧并保留 16pt 安全间距，纵向居中。
5. 再次划词时旧内容应被新任务替换，不残留旧状态。

## 12. 技术约束

1. 平台仅限 macOS 13+。
2. 使用 `NSPanel + SwiftUI（NSHostingView）` 实现悬浮面板。
3. 读取划词内容双通道：Accessibility API + 模拟 ⌘C 剪贴板兜底。
4. 无标题栏浮层通过 `.borderless` + `.fullSizeContentView` 实现；工具栏允许背景拖拽，结果侧栏禁用拖拽并固定定位。
5. 应用入口为菜单栏模式（`.menuBarExtra`），激活策略为 `.accessory`（无 Dock 图标）。
6. Swift Package Manager 管理依赖，Xcode 项目文件用于构建和签名配置。

## 13. 验收标准

### 13.1 功能验收

1. 用户完成 API Key 配置和权限授权后，可以在 Safari/Chrome 等网页、Xcode/VS Code/JetBrains 等 IDE，以及 Codex 对话界面稳定划词触发工具栏。
2. 翻译、解释两个 MVP AI 动作均能返回结果。
3. 支持继续提问（推荐问题 chips + 自由输入）。
4. 支持复制原文、复制结果、重试、关闭。
5. Accessibility 不可用的应用能通过 ⌘C 兜底方案正常获取选中文本。
6. ⌘C 兜底方案不应覆盖截图工具或用户在同一时间窗口内写入的新剪贴板内容。
7. 自动化状态机测试必须证明：只触发 `mouseDown + mouseDragged`、尚未触发 `mouseUp` 时，已能发布第一个可读选区并显示工具栏。

### 13.2 交互验收

1. 工具栏横向按钮形态清晰，交互流畅。
2. 结果面板的顶部、原文区、内容区、底部操作栏、继续提问区层级清晰。
3. 加载态、错误态、成功态切换自然，无明显闪烁。
4. 面板不会出现在屏幕外或被 Dock/Menu Bar 遮挡。
5. ESC 键可关闭工具栏与结果侧栏；点击面板外仅关闭工具栏，不关闭结果侧栏。

### 13.3 视觉验收

1. 视觉风格为 macOS 26 Liquid Glass：玻璃用于悬浮控制层和侧栏外壳，内容阅读层保持白色不透明。
2. 工具栏圆角 15pt、结果侧栏圆角 28pt，SF Symbols、间距和同心圆角保持一致。
3. 信息密度适中，层级主要靠间距、字重和不触边的弱分隔线区分。
4. 主题背景必须为白色磨砂微透明，外缘透明度高于主题背景；“继续提问”输入框保持高不透明度，不使用额外折射效果。

## 15. 实现架构

### 15.1 组件关系

```
HaxPickApp (SwiftUI @main, MenuBarExtra)
  └── AppDelegate (启动入口)
        └── AppState (单例，中心状态管理)
              ├── SelectionMonitor (全局鼠标事件监听)
              │     ├── AccessibilityTextService (通道一：辅助功能 API)
              │     └── ClipboardSelectionService (通道二：模拟 ⌘C)
              ├── ToolbarPanelController (NSPanel 管理)
              │     ├── PanelSessionViewModel (面板状态)
              │     └── FloatingToolbarView (SwiftUI 视图)
              └── DeepSeekService (API 请求)
```

### 15.2 关键文件

| 文件 | 职责 |
|------|------|
| `HaxPickApp.swift` | 应用入口，MenuBarExtra UI |
| `AppDelegate.swift` | 启动回调 |
| `AppState.swift` | 单例状态管理，协调各组件 |
| `SelectionMonitor.swift` | 全局鼠标事件监听，划词检测 |
| `AccessibilityTextService.swift` | 通过 AX API 读取选中文本和坐标 |
| `ClipboardSelectionService.swift` | 模拟 ⌘C 获取文本，剪贴板保存/恢复 |
| `ToolbarPanelController.swift` | NSPanel 创建、定位、事件处理 |
| `FloatingToolbarView.swift` | SwiftUI 工具栏/结果面板视图 + ViewModel |
| `DeepSeekService.swift` | DeepSeek API 调用、Prompt 构建、错误处理 |
| `Package.swift` | Swift Package Manager 配置 |

## 16. 当前假设

1. "完全参考HaxPick"理解为产品交互、布局和信息层级对齐，不代表需要品牌素材、图标或文案逐字复刻。
2. "依赖 DeepSeek API"理解为模型服务端完全使用 DeepSeek，不接第三方中转层。
3. 当前项目继续沿用现有 macOS App 架构，不改成浏览器扩展或输入法插件。
4. 双通道划词读取方案可覆盖主流 macOS 应用的绝大多数场景。
